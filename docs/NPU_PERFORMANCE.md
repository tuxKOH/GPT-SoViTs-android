# Snapdragon 8 Elite QNN 实机性能与正确性记录

2026-09-24，ASUS AI2501C / SM8750 / HTP V79，QAIRT 2.48.0.260626，已安装的 Firefly V2PP SM8750 QNN pipeline 和 voice attachment。测试文本「你好，这是性能测试。」。所有手工测试音频、结果和新版 ORT profile 均写入 `/sdcard/models/gs/gs-acceptance`；应用界面测试后立即退到后台。QNN 长时验收在系统内存压力下曾因应用被归为缓存进程而遭系统杀进程，随后用现有本地 API 前台服务临时保活，在不占用屏幕的状态下完成测试，并在结束后停止服务。

## 验收范围

优化前，内置参考音频、临时参考音频、OpenAI 预设和 OpenAI 临时参考四条实际合成路径均通过非静音、非削波检查。优化后四条路径再次通过；优化后的一轮完整验收有 45 个 ORT profile、371 次 `Node` 事件，全部由 `QNNExecutionProvider` 执行，`CPUExecutionProvider` 节点为 0。前端文本规范化、抽样、张量组装及 PCM 写出仍在 CPU 上，因此这不表示整个 App 或全部时间都在 NPU 上。验收 JSON 的 `runner_passed=true` 是引擎/API 通过，`product_acceptance_complete=false` 仍提示 UI 流程与音质主观验收不在此项测试内。

## 瓶颈与改动

原 T2S 自回归步骤每 token 都从 Kotlin `ShortArray` 重新构造两个完整 FP16 K/V 缓存张量，各约 24 MiB；每轮约 48 MiB 的 JVM/ORT 数据搬运。原预设测试 52 次 QNN T2S 节点总执行时间 1.42 秒，但从步骤会话建立到结束约 13.62 秒。VITS 六个分区也包含会话初始化与 NPU 计算，较后面的分区单次计算约 1.4–2.4 秒，不应误报为 CPU fallback。

现将 K/V 缓存放在复用的直接内存中，仅把新 token 的一个槽位写回，并在整个自回归阶段复用两个 ORT 输入张量。没有修改 FP16 数值、图、权重或采样选项。优化后的一次预设测试产生 131 次 QNN T2S 节点，总 NPU 节点时间 3.81 秒，步骤会话约 4.63 秒；平均每次节点对应的墙钟时间从约 262 毫秒降到约 35 毫秒。两次采样 token 数不同，不能用整句时间直接计算同倍率提升；按 token 计约 7.4 倍仅反映这组测试中的 T2S 调用开销。完整端到端速度仍受 VITS 与冷热装载主导，且需要更多温度与重复样本才能给出稳定速度承诺。

最终 APK 的一次预设合成 sidecar 记录整段 21.49 秒、进程 CPU 时间 10.52 秒，WAV 为 32 kHz、120,320 个采样点；同文本 CPU 默认 8 线程样本为 33.32 秒。两次语义 token 数与输出长度不同，不能把这两个整句耗时直接当作固定加速比。

调试 profile 现只在验收显式指定输出目录时生成，不再默认写入已安装模型目录。用户模型和 QNN 附件仍保留在 `/sdcard/models/gs` 或 App 的正式安装目录；测试临时文件不可放在 `/sdcard` 根目录。
QNN 合成现在也输出与 WAV 同名的 `.timing.json` 分段计时文件，可在后续真机复测时区分前端、参考条件准备与整段合成耗时。

## VITS 会话复用实验（同日）

后续将六个 VITS 分区的 ORT/QNN 会话缓存在当前已加载的模型实例内，仅保留预设或临时参考中的一套；两种参考路径切换时先关闭旧套，切换模型时随执行会话一并关闭。调试验收开启逐图 ORT profile 时仍使用一次性会话，保证 profile 能及时落盘。这没有改变模型图、权重、FP16 值或 HTP 后端设置。

SM8750 上用相同文本连续进行预设和 OpenAI 预设合成，首次六段 VITS 会话建立总计 7.02 秒、VITS 运行 9.39 秒；第二次六段会话均复用（无建立事件），VITS 运行 10.30 秒。随机生成的语义长度不同，整句耗时不能直接比较。该优化减少的是同一模型、同一参考类型的后续合成启动开销，不缩短首次合成；参考类型交替时会重新建立会话，不能期待此项收益。

缓存版的预设、临时参考语音及对应的 OpenAI 两种请求均通过实际 WAV、非静音、非削波验收，结果在设备 `/sdcard/models/gs/gs-acceptance/qnn-session-cache-reference/`；连续预设验收在 `qnn-session-cache-final/`。后者首次整句 24.39 秒，但输出长度仅 66,560 采样点，不能与先前不同长度的 21 秒样本直接比快慢。尝试固定随机种子时，现有模型包明确拒绝未声明的 `seed` 选项，因此没有进行逐样本确定性对比。测试期观察到应用 PSS 约 580 MiB；该值不包含可准确归属的 DSP 内存，长期驻留和更高并发仍需监测。调试保活服务在验收后已停止，手机前台没有被长期占用。

2026-09-24 又加入了当前模型会话内的短句 PCM LRU 缓存：规范化片段不超过 80 个 Unicode 码点、输出不超过 5 秒时才保存，最多占 24 MiB。缓存键包含语言、全部合成参数、显式随机种子和参考语音音频/文本的 SHA-256 指纹；切换模型或关闭会话即清除。命中时跳过 BERT、T2S、VITS 及临时参考语音的条件计算，复用此前已经验收的 PCM；这不是对首遍推理的提速，也不会预生成未知短句或修改音质。随机种子未指定时，重复短句按复用语音片段处理，这是缓存功能的预期行为。

同机真机验收使用「你好，这是性能测试。」：第一次 QNN 合成 28.86 秒（含冷启动与图会话建立），随后 OpenAI 同文本请求记录 `qnn.phrase_cache.hit`，合成 1.39 秒；两份 113,920 采样点 WAV 的 SHA-256 完全相同。结果在 `/sdcard/models/gs/gs-acceptance/qnn-phrase-cache/`，前台已退回系统桌面；该轮只覆盖预设音色，临时参考语音的缓存隔离由键设计与单元测试覆盖，仍需另做设备复测。

最终 APK 另以 profile 模式跑了两次预设合成，`qnn-session-cache-profile/` 的 19 个 ORT profile 共含 198 个 `Node` 事件，全部为 `QNNExecutionProvider`；该模式为及时结束并审计 profile 而关闭 VITS 会话复用，因此节点归属审计和热态复用计时来自两轮独立验收。`./gradlew -PacceptanceAbi=arm64-v8a :app:testDebugUnitTest` 通过。
